# 単体テスト手順: NOIM構成図の可視化

## テストフレームワーク

- Python 標準ライブラリの `unittest`(追加インストール、設定ファイルは不要)。
- 新しいテストファイル: `tests/test_visualizer.py`(1ファイル)。既存の `tests/test_input.py`、`test_converters.py`、`test_output.py`(42件)は変更しない。

## 実行コマンド

ワークスペース直下で実行する。

この変更のテストだけ:

```bash
python3 -m unittest tests.test_visualizer -v
```

既存のテストも含めた全体(既存の42件が成功のままであることの確認):

```bash
python3 -m unittest discover -s tests -t . -v
```

## テスト方針(Minimal)

- 要件ごとに1件以上。コンポーネント(loader、graph、layout、html_out、CLI)ごとに、正常系を1件以上。約14件。
- 入力は、小さな合成データ(辞書から作る出力CSV、辞書から作るアラームJSON)を `tempfile.TemporaryDirectory` に書いて使う。固定のテストデータファイルは持たない。
- 通し実行(1件): `入力ファイル/` の3ファイルを、既存の変換ツール(`noim_converter.run`)で一時ディレクトリに変換し、更新後の `アラーム/alarm_sample.json` で可視化する。装置26、アラームが該当装置に付くこと、描けない接続の件数が警告に出ること、`password` の値(テスト内で入力に差し込んだ値)がHTMLに無いことを確認する。
- HTMLの見た目(表示、ドラッグ、拡大縮小)は、自動テストでは確認しない。人が、ブラウザで開いて確認する(NFR2)。自動テストが確認するのは、HTMLの内容(埋め込みデータ、色の割り当て、外部URLが無いこと)。
- 一時ディレクトリの外のファイル(`入力ファイル/`、`アラーム/`)は、読み取りだけを行う。

## 期待するカバレッジ

- 行カバレッジの下限は設定されていない(express の Minimal)。要件ごとの検証を満たすことを目標とし、閾値の設定ファイルは作らない。

## モック/スタブの指針

- ファイルシステムはモックせず、実際の一時ディレクトリを使う。
- ブラウザは使わない(HTMLの文字列を検査する)。

## テストデータ

- 各テストが、必要な出力CSVとアラームJSONを自分で作る。出力CSVは `"objectId","data"` の2列で、`data` はJSON文字列(`noim/output_csv.py` と同じ形式)。
