# Requirements: NOIM構成図の可視化とアラーム装置の見える化

## Intent Analysis

**依頼:** NOIM変換ツールの出力(装置と装置間の接続情報)を構成図として可視化し、S3に置いたアラームファイル(JSON)を読み込んで、アラームが発生している装置を見える化したい。

**決まったこと(質問の回答)**

| 項目 | 決定 | 根拠 |
|---|---|---|
| 装置とアラームの結びつけ | アラームの `targetDeviceId` に、NOIMの装置名(`commonName`)と同じ文字列を入れる。アラームの仕様書とサンプルをこの形に書き換える | Q1: A |
| 図に出す接続 | 物理接続(PLink、TL)と、LSPの論理接続(FRE の NC)の両方。線の見た目で区別する | Q2: A |
| 見せ方 | ブラウザで開く Web ページ(1つのHTMLファイル) | Q3: A(QuickSight は構成図を描けず、時間にも合わないため見送り) |
| 見る場所 | ローカルの本PCだけ。AWS上での公開、認証は作らない | Q4: Other |
| 反映の方法 | 手元で動く Python スクリプトが、S3からダウンロードした出力CSVとアラームJSONを読み、1つのHTMLを作る。AWS側に新しいものは作らない | Q5: A |
| アラームの表示 | `active` のアラームがある装置だけを強調。重大度で色分け(1 黄、2 橙、3 赤)。複数なら最も重い色。クリックで一覧。`recovered` は一覧にだけ薄く表示 | Q6: A |

**ゴール:** 今日の16:15までに、実データ(装置26、接続32)とサンプルのアラームで動く可視化を、ローカルPCのブラウザで確認できること。

## Functional Requirements

### FR1 入力の読み込み

- **FR1.1** システムは、NOIM変換ツールの出力ディレクトリ(`resourceInfo_*.csv`)から、構成図に必要なリソース(装置 PD、物理接続 PLink と TL、LSPの論理接続 FRE、およびそれらをつなぐ PPort と TPE)を読み込むこと。
- **FR1.2** システムは、アラームJSON(`アラーム/alarm_spec.md` の形式)を読み込むこと。
- **FR1.3** 入力の不足や不正(ファイルが無い、JSONが壊れている、必須項目が無い、`alarmLevel` が1〜3以外、`status` が `active` と `recovered` 以外)があるとき、システムは、ファイル名と理由を示して止めること(読み飛ばさない)。

  *受け入れ条件:* Given 出力ディレクトリに `resourceInfo_pds.csv` が無い。When スクリプトを実行する。Then ファイル名を示すエラーを表示して、終了ステータス1で終わり、HTMLは作られない。

### FR2 構成図の組み立て

- **FR2.1** システムは、装置(PD)1件につき1つの点を作り、表示名を装置名(`commonName`)にすること。
- **FR2.2** システムは、物理接続(PLink、TL)を、2つの装置を結ぶ実線にすること。
- **FR2.3** システムは、LSPの論理接続(FRE の NC)を、2つの装置を結ぶ点線にすること。
- **FR2.4** 接続の端が装置に結びつかないとき、システムは、その接続を描かず、描けなかった件数と理由を画面の警告に出すこと。
- **FR2.5** `VPN回線(BR)` のサービスは、変換で接続リソースにならないため、図の対象にしないこと。

  *受け入れ条件:* Given サンプルの実データ(装置26、物理接続24、LSP接続8)。When HTMLを作る。Then 図に装置26点と、結びつけられた接続の線が描かれ、描けなかった接続があれば件数が警告に表示される。

### FR3 アラームの結びつけ

- **FR3.1** システムは、アラームの `targetDeviceId` が装置の `commonName` と完全に一致するとき、そのアラームをその装置に結びつけること。
- **FR3.2** 一致する装置がないアラームは、システムが、画面の「対応する装置のないアラーム」の一覧に出すこと(エラーにしない)。
- **FR3.3** システムの一部として、`アラーム/alarm_spec.md` と `アラーム/alarm_sample.json` を、`targetDeviceId` に装置名を入れる形に更新すること(サンプルは実データの装置名を使う)。

  *受け入れ条件:* Given `targetDeviceId` が実在する装置名のアラームと、存在しない装置名のアラーム。When HTMLを作る。Then 前者は該当装置に付き、後者は「対応する装置のないアラーム」に出る。

### FR4 画面の表示

- **FR4.1** 画面は、1つのHTMLファイルで完結し、インターネットに接続していなくても開けること(外部のライブラリやサービスを読み込まない)。
- **FR4.2** 画面は、装置を自動で配置し、拡大・縮小と、装置のドラッグができること(NOIMの座標は全装置 `"0"` で使えない)。
- **FR4.3** 画面は、`active` のアラームがある装置を強調し、重大度で色分けすること(1 黄、2 橙、3 赤)。装置に複数の `active` があるときは、最も重い重大度の色にすること。
- **FR4.4** 画面は、装置をクリックすると、装置の情報(名前、種別 `node_type`)と、その装置のアラーム一覧(`alarmId`、`alarmName`、`alarmLevel`、`occurredAt`、`status`)を表示すること。`recovered` のアラームは、強調せず、一覧にだけ薄く表示すること。
- **FR4.5** 画面は、上部に、装置数、接続数(物理とLSP)、`active` のアラームがある装置の数、警告の件数を表示すること。

  *受け入れ条件:* Given `active` の重大度3と重大度1のアラームを持つ装置。When その装置を見る。Then 赤で強調され、クリックすると2件の一覧が出る。Given `recovered` だけの装置。When 見る。Then 強調されない。

### FR5 データの保護

- **FR5.1** システムは、入力の認証情報の列(`username`、`password`、`telemetry_*` など)を、HTMLに含めないこと。表示に必要な項目だけを取り出す方式にすること(取り除く方式にしない)。

  *受け入れ条件:* Given 出力CSVの `nttManagementInfo` に `password` の値がある。When HTMLを作る。Then その値はHTMLのどこにも含まれない。

### FR6 実行

- **FR6.1** システムは、次の形で実行できること: `python3 visualizer.py <NOIM出力ディレクトリ> <アラームJSON> <出力HTML>`。
- **FR6.2** 同じ入力からは、同じHTMLを作ること(装置の初期配置も含む)。
- **FR6.3** システムは、終了ステータスを 成功 0、入力・処理の失敗 1、引数エラー 2 とし、エラーを標準エラー出力へ出すこと(変換ツールと同じ約束)。

## Non-Functional Requirements

- **NFR1** (保守性・可搬性) スクリプトは Python の標準ライブラリだけで動き、画面の JavaScript も外部ライブラリを使わないこと。
- **NFR2** (性能) 実データ(装置26、接続32、アラーム数十件)のHTMLを、ブラウザで開いてから3秒以内に描き終えること。
- **NFR3** (セキュリティ) 認証情報を含むデータをブラウザに渡さないこと(FR5.1)。HTMLの作成と閲覧は、ローカルのPCだけで完結し、AWS上に公開しないこと。
- **NFR4** (運用) AWS上に、新しいリソースを作らないこと(CDK、デプロイは今回の対象外)。

## Constraints

- PoCであり、16:15(日本時間、2026-11-13)までに動くものを作ることを優先する。作り込みはしない。
- 入力のファイルは、人がS3のコンソールからダウンロードして用意する。スクリプトはAWSに接続しない。
- アラームJSONの形式は、`アラーム/alarm_spec.md` に従う(`targetDeviceId` の中身は FR3.3 で変更する)。

## Assumptions

| # | 内容 | 理由 |
|---|---|---|
| A1 | `[assumption]` スクリプトは、この作業環境、または Python 3 が入ったPCで動かす。HTMLは、PCのブラウザで開く | 依頼は「ローカルの本PCで見られればよい」 |
| A2 | `[assumption]` 装置の名前(`commonName`)は、一意である(サンプルでは26件すべて一意) | コード調査の結果。重複があれば、FR3.1 の結びつけが曖昧になるため、重複が見つかったらエラーにする(設計で扱う) |
| A3 | `[assumption]` 装置は数十台、接続は百本程度までを想定する | サンプルの規模 |
| A4 | `[assumption]` アラームJSONの `occurredAt` は、そのまま文字列で表示する(日時の計算はしない) | 並べ替えや集計の依頼がない |

## Out of Scope

- AWS上での公開(CloudFront、S3の静的ホスティング)、認証(Basic認証、WAF、Cognito)、Lambda、QuickSight
- 画面の自動更新、S3の変更の自動検知、アラームの履歴や集計、アラームの確認操作
- 地図上の配置(座標が使えないため)、`VPN回線(BR)` の表示
- 変換ツール、EC2、CDKの変更
