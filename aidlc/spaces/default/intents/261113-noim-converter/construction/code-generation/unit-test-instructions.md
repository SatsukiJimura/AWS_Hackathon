# 単体テスト手順: NOIM変換ツール

## テストフレームワーク

- Python 標準ライブラリの `unittest`(追加インストール、設定ファイルは不要)。
- テストファイル: `tests/test_*.py`(入力、変換、出力・コマンドラインの3ファイル程度に分ける)

## 実行コマンド(このコードのテストのみ)

ワークスペース直下で次を実行する。

```bash
python3 -m unittest discover -s tests -t . -v
```

## テスト方針(Minimal)

- 要件ごとに1件以上。変換は種別ごとに1件以上の正常系と、主な分岐(CEと非CE、XCの共有、エラー)を確認する。
- 変換のテストは、数行の小さな合成データ(辞書やCSV文字列)を使う。実データは通し実行のテスト(1件)だけで使う。
- キー名のテスト: PDの `nttManagementInfo`、PPortの `nttManagementInfo`、PLinkの `nttManagementInfo` のキー一覧を、外部インタフェース仕様書の一覧(`インタフェース仕様書/外部インタフェース仕様書.xlsx` の 1.8 PD、1.7 PPort、1.9 PLink)から一度だけ取り出してテストに埋め込み、出力のキーの順序と一致することを確認する。xlsx自体はテストで読まない。
- 通し実行のテスト: `入力ファイル/` の3ファイルを一時ディレクトリへ出力し、終了ステータス0、8ファイルの生成、各ファイルのヘッダ(`"objectId","data"`)、全フィールドのクォート、CRLF、BOMなし、各行の `data` がJSONとして読めること、objectIdの重複がないこと、リソース間で参照しているobjectId(`_tpeIdRef`、`_physicalPort`、`_aEndTpeRefList` など)がすべて出力内に存在することを確認する。
- 一時ディレクトリ(`tempfile.TemporaryDirectory`)の中で入出力を行い、プロジェクト内のファイルは変更しない(`入力ファイル/` は読み取りのみ)。

## 期待するカバレッジ

- 行カバレッジの下限は設定されていない(express の Minimal)。要件ごとの検証を満たすことを目標とし、閾値の設定ファイルは作らない。

## モック/スタブの指針

- ファイルシステムはモックせず、実際の一時ディレクトリを使う。
- 書き込み失敗は、出力先に同名のディレクトリを置くなどで実際に失敗させる。環境依存で再現できない場合のみ `unittest.mock` で `os.replace` を失敗させる。

## テストデータ

- 各テストが一時ディレクトリに必要なファイルを自分で作る。共有の固定データは持たない(通し実行用の `入力ファイル/` を除く)。
- 設計書の変換例(サンプル入力と期待結果)はない。期待結果との一致確認は、テスト内で出力を一度生成して比較する形で機能を確認する。
