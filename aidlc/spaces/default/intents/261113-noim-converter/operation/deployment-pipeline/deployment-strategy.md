# Deployment Strategy: NOIM変換ツール

## 方式

**Recreate(置き換え)。**

| 項目 | 内容 |
|---|---|
| 仕組み | 変換ツールのコードを変えて `cdk deploy` すると、EC2 が新しく作られて、古いものが消える。コードは EC2 の起動時に配置される |
| 選んだ理由 | 変換ツールは、人が実行するバッチで、常時のサービスではない。止まっても利用者に影響がない。インスタンスを1台しか持たないので、ローリング、カナリア、ブルー/グリーンの利点がない |
| 退けた案 | Blue/Green(EC2とコストが2倍)、Canary / Rolling(複数台と負荷分散が前提) |
| 停止時間 | デプロイ中の数分間、EC2 に入れない。データは S3 にあるので失われない |
| データ | S3 の `input/` と `output/` はデプロイで消えない(スタックを `destroy` すると消える) |

## 変更の種類ごとの扱い

| 変更 | 結果 |
|---|---|
| 変換ツールのコード(`noim_converter.py`、`noim/`) | EC2 が置き換わる(ユーザーデータが変わるため) |
| `infra/` のコード(CDK) | 変更した部分のリソースだけが更新・置き換え(`diff` で事前に確認) |
| 入力CSV | デプロイ不要。S3 に置いて `sudo noim-run` |

## デプロイ前の条件

- 単体テスト42件が成功していること
- `cdk synth` がエラーなく通ること
- `cdk diff` の内容を、人が確認していること

## デプロイ後の確認(スモークテスト)

1. スタックが `CREATE_COMPLETE`(更新なら `UPDATE_COMPLETE`)
2. EC2 にセッションマネージャーで接続できる
3. `sudo noim-run` が「完了」と表示して終わる
4. S3 の `output/` に `resourceInfo_*.csv` の8ファイルがある

中断条件: 上のどれかが満たされない場合は、成功とみなさず、`rollback-runbook.md` に従う。

## デプロイの時間帯

制限はありません(利用者が自分だけの PoC のため)。
