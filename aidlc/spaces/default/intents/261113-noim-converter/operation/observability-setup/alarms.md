# Alarms: NOIM変換ツール(dev)

PoC のため、**すでにデプロイ済みのアラーム1つだけ**を使います。新しく追加するものはありません(通知先を作る場合は、下の「通知を付けたいとき」を参照)。

## 設定済みのアラーム

| 項目 | 内容 |
|---|---|
| 名前(CDK の論理ID) | `StatusCheckFailedAlarm`(`infra/noim_stack.py`) |
| 目的 | EC2 が壊れて、SSM で入れない状態に気づく |
| メトリクス | `AWS/EC2` の `StatusCheckFailed`(統計: 最大値、期間: 1分) |
| 条件 | 0 より大きい状態が、5回連続(5分間) |
| データ不足のとき | 異常とみなさない(`NOT_BREACHING`) |
| 重大度 | 低(P3 相当。チケット・確認で足りる。夜間に呼び出す対象ではない) |
| 通知先 | **なし**(アラームの状態がコンソールに表示されるだけ) |
| 対応 | `rollback-runbook.md` の「C. 接続できないとき」、直らなければ「A. コードを前の版に戻す」(EC2 の作り直し) |

## ガードレールとの対応(Operation フェーズ)

| 指針 | この構成 |
|---|---|
| 新しいコンポーネントに、健全性のメトリクスを1つ以上 | あり: `StatusCheckFailed` |
| 新しいコンポーネントに、エラー率のメトリクスを1つ以上 | **なし(意図した例外)。** 変換ツールは人が実行するバッチで、リクエストの流れが無く、エラー率を計算する分母がない。代わりに、実行ごとの終了ステータスと `/var/log/noim-run.log` のエラーメッセージを見る(人が `sudo noim-run` の結果を見る運用) |
| アラームのしきい値は SLO の違反より前に | 該当なし(SLO を設けない。`slo-config.md`) |
| ランブックに、エスカレーション先と連絡先 | 個人の PoC のため、デプロイした本人だけ。`rollback-runbook.md` に記載済み |

## 通知を付けたいとき(今回は未実施)

メールで通知する場合は、CDK に次を足します(SNS トピックとメール購読を作り、アラームに紐づける)。必要になった時点で依頼してください。メールアドレスと、購読の確認メールへの承認が必要です。
